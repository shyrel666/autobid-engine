# D4 成稿与提交验收记录（E 级，本机）

验收日期：2026-11-16。对应 [ROADMAP.md](../ROADMAP.md) 第四节 D4、[RELIABILITY_PLAN.md](RELIABILITY_PLAN.md) 的 R3。运维与升级说明见 [OPERATIONS.md](OPERATIONS.md) 第 5 节。

本记录只证明工程实现（E）。样本是合成的，浏览器验收的模型是脚本替身（`web/e2e/stub_llm.py`）。评分索引是否方便评委、成稿能否导入交易平台、承诺与台账比对的检出率，都没有外部验证（V / P 未开始）。

## 1. 声明范围

一份严格最终稿现在包含并保证下列内容：

- **评分索引。** 目录之后是《评分索引表》：技术 / 商务评分项（价格分不进技术标）按评分表顺序列出，每项给出响应它的章节与页码。每个章节标题下面有一行“响应评分项：……（N 分）”。
- **附录。** 《点对点应答及偏离表》每行带应答章节的页码，有证明材料的条款指明它在《证明材料索引》中的序号；《承诺事项一览表》由已确认的承诺台账渲染；《证明材料索引》列出正文引用的、当前可采的企业证据及其原件页码范围。
- **页码是核对过的。** 上述页码都是指向章节标题的页码域，由 WPS / Word 与目录一起刷新。同一次排版同时导出 DOCX 和 PDF，成稿里的每一处页码都与 PDF 版面中该标题实际所在的页逐一比对；有一处不一致，最终稿就失败，不交付。
- **文档属性只含投标人。** 作者、最后修改者只写导出时填写的投标人名称；不带系统字样、不带本机办公软件账号、不带内部段落编号。DOCX 与 PDF 都回读核对。新的最终稿必须填写投标人名称。
- **承诺以台账为准。** 一致性核验把正文里的每处关键承诺（工期、质保、响应 / 到场 / 修复时限、可用性、团队人数）与已确认的承诺台账比对，不一致记为待处理结论并阻断导出。
- **提交检查清单。** 每份最终稿有一张清单：系统可查项由成稿的回读结果判定，人不能改；封面核对、签字盖章、证明材料附入、交易平台导入、加密上传等由人逐项确认，记录确认人、时间、说明与凭证编号，每次确认、改判、撤回都留痕。导出之后正文再有改动，这份成稿即标为过期，不能再确认。

不在范围内：

- 证明材料原件不合入成稿。索引给出的是原件文件内的页码，原件扫描件由投标人按索引顺序另行附入。
- 系统只生成技术标。商务响应、报价文件、承诺函、人员表不由系统生成，也不在一致性比对范围内。
- 清单“已全部处理”不表示已在交易平台提交。签章和上传都在系统之外，系统只记录有人确认过。
- 没有在任何交易平台的投标文件制作工具里验证过成稿能否导入。
- “当前操作人”只是审计声明，可以伪造（可信身份属于 R2 / Phase 7）。
- 跨企业的正文相似度没有比对；使用内置模板的企业版式相同，清单要求人写明理由后确认知悉。

## 2. 环境与方法

方法：

- 页码核对用的是真实 WPS 排版出来的文件：测试直接回读产物 DOCX 里每个页码域的结果，再到同一次导出的 PDF 版面里找标题实际所在的页，两者逐处比较。不依赖作业里记录的结论。
- 成稿另外人工看过一遍渲染出来的页面（目录、评分索引表、正文首页、三张附录）。3.5 节的两处问题就是这样发现的，自动测试当时都没有覆盖到。
- 浏览器套件由 Go 测试启动真实服务进程，连接隔离库，使用真实 WPS、Mermaid 与 PaddleOCR。

### 3.5 过程中发现并修复的问题

前六项是既有问题，D4 的测试或人工查看成稿时暴露；后五项出在 D4 自己的实现里。

| # | 问题 | 怎么发现的 | 处理 |
| --- | --- | --- | --- |
| 1 | 一致性抽取把含“招标文件 / 招标要求”的句子整句跳过。“我方承诺免费质保期 5 年，优于招标要求”这类最常见的承诺句从不参与任何比对 | 台账比对的集成测试没有产生预期结论 | 引述只作用于引述词之后；引述之后出现“我方”等自称再恢复。规则版本升为 `consistency-v2` |
| 2 | 响应核验把计分步长当成门槛：“质保期每延长一年得 1 分”使“承诺 5 年”被判为“要求一年，应答 5 年”的负偏离，并阻断导出 | 附表快照的集成测试被导出门禁拦住 | 抽取数值门槛时去掉“每……得 / 加 / 扣 N 分”；同一要求里的真实门槛仍然生效 |
| 3 | 升级前的一致性结论没有与台账比对过，却能通过新的导出门禁 | 设计复核 | 运行记录规则版本，旧版本的运行不算当前结论 |
| 4 | 承诺台账的数值口径不一：从原文解析的值归一到天，直接填写的值按单位计。“阈值 不少于 3 年 + 承诺值 5（单位 年）”被比成 5 < 1095 而拒绝确认 | 新夹具确认承诺时被拒 | 解析出的数值换算到台账声明的单位 |
| 5 | 承诺原文自带单位时，成稿里写成“90 天 天” | 人工查看渲染出的 PDF | 原文只是数字时才补单位 |
| 6 | 偏离表的“应答章节”带着内部段落锚点，如“（p1-aca50601）”：评委看不懂，也是所有导出文件共有的可识别格式 | 人工查看渲染出的 PDF | 成稿只给章节与页码 |
| 7 | 没填投标人的导出，PDF 的作者是本机 WPS 账号（`WPS_<数字>`）。原因是 D4 让 PDF 作业同时另存 DOCX，而 WPS 另存时会把空作者填成登录账号 | 新增的文档属性回读在全量回归里报出 | 先导出 PDF 再另存 DOCX；补了不填投标人时 PDF 作者为空的断言 |
| 8 | 没填投标人的最终稿能生成，但封面为空、过不了清单，只能重导 | 设计复核 | 新的最终稿请求不带投标人名称时拒绝（400），页面在提交前拦住 |
| 9 | 请求哈希含策略版本：策略由 v1 升到 v2 后，升级前的最终稿请求用同一个键重发会被判成“同键异参” | 代码复核 | 重放按原请求提交时的策略版本求哈希 |
| 10 | 导出页没有“当前操作人”输入框，清单在这一页根本无法确认 | 浏览器全流程第 32 步失败 | 导出页加入该输入框 |
| 11 | 标题一行排不下时，回读在 PDF 里找不到这个标题，严格最终稿因此失败；目录的第一个条目折行时也会解析错 | 代码复核，随后在夹具里加入长标题实测 | 同字号的相邻行拼接后再匹配；目录标题之后的第一条允许折行 |

## 4. 边界

- 所有样本都是合成的。规则抽取（承诺、评分项）的召回率和误报率没有在真实投标稿上测量；“没有不一致结论”不代表全文与台账一致。
- 一致性只比较同一指标的数值，不理解分阶段、分子系统的语境；同一指标有多条台账（如核心设备与其余设备的质保期）时，与任意一条一致即算通过。
- 页码核对按“标题文字在 PDF 中字号最大的一处”定位标题。两个章节标题文字完全相同时无法区分。
- Word 引擎只跑了 D4 的一条真实用例，其余真实引擎用例都在 WPS 上。
- 真实企业模板没有逐份适配；模板占位符须在同一文字段内。
- 升级前的最终稿没有回读记录，不能直接走清单，需要重新导出。
