# AutoBid 本机运维手册

适用范围：运行 AutoBid 服务的这台 Windows 机器。业务人员只用浏览器，本文给维护这台机器的人看。

本文的备份、校验、恢复、升级和回退步骤都在 `cmd/upgrade-drill` 中用真实旧程序和真实数据库实际跑过，记录见 [S7_ACCEPTANCE.md](S7_ACCEPTANCE.md)。组件版本和安装方法见 [LOCAL_RUNTIME.md](LOCAL_RUNTIME.md)。

## 1. 启动与停止

```bat
start.bat
```

- `start.bat` 构建前端、服务端和运维工具，启动本机 OCR，再启动服务，并在崩溃后自动重启。
- 停止：在启动窗口按 Ctrl-C。OCR 在名为 `autobid-ocr` 的最小化窗口里运行，要单独关闭。
- 只构建不启动：`start.bat --build-only`。

几条硬性限制：

- 要在已登录的桌面会话里运行。WPS / Word 走 COM 自动化，不能作为 Windows 服务运行。
- 同一数据库只能运行一个服务实例，Planner 和活动流都在进程内。
- 服务运行时不要跑含真实文档引擎的测试，服务不走测试用的排队锁。

## 2. 日常检查

```bat
ops.bat check
```

它只读取，不迁移、不启动 WPS、不调用模型。结果分三类：

| 项目 | 不通过时 |
| --- | --- |
| 数据库版本 | 程序和数据库不匹配。升级后第一次启动前出现是正常的 |
| 在途作业（导出、图表、解析、章节写作、索引构建、运行中的任务） | 不要停机或升级，先等完成或取消；运行中的项目可以先在页面暂停 |
| 数据目录（招标原件、导出产物、证明材料） | 目录不可写或磁盘有问题，先处理 |
| 文档引擎、Mermaid、OCR、语义模型 | 对应能力不可用，不影响其它功能。实际能力以服务启动自检为准 |

前三类不通过时退出码为 3，其余只作提示。暂停的项目也只作提示：暂停时没有在途工作，重启后仍为暂停。加 `--json` 输出机器可读结果。

页面上的“运行能力”按钮显示每项能力的状态、影响和下一步；面板底部的“诊断详情”显示运行版本和数据库版本。

## 3. 备份

**备份前先停止服务**（Ctrl-C），并确认 `ops.bat check` 通过。

```bat
ops.bat backup --out D:\backup\autobid-2026-11-06
ops.bat verify --dir D:\backup\autobid-2026-11-06
```

- 备份目录必须为空或不存在，已有内容时拒绝执行。
- 先导出数据库，再复制文件。这样文件总是数据库引用内容的超集，多出来的文件无害。
- 包含：PostgreSQL 全库（`pg_dump -Fc`）、招标原件、导出产物、证明材料。`manifest.json` 记录版本和每个文件的 SHA-256。
- **不包含模型主密钥。** `AUTOBID_LLM_MASTER_KEY`，或 `AUTOBID_LLM_KEY_FILE` 指向的文件（默认 `data/llm-master.key`），要单独保管。丢失后已保存的模型凭据无法解密，只能重新填写。
- `.env.local.bat` 里有数据库密码和 API Key，同样不在备份内，要单独保管。
- 备份里有招标文件和企业证明材料原件，按敏感数据保管。

`pg_dump` 从 `AUTOBID_PG_BIN`、PATH、`C:\Program Files\PostgreSQL\16\bin` 依次查找。

## 4. 恢复

恢复只写入**空的新数据库和空目录**，没有覆盖选项。

1. 新建空数据库：

   ```bat
   "C:\Program Files\PostgreSQL\16\bin\createdb.exe" -U postgres autobid_restore
   ```

2. 把目标连接串放进一个环境变量（不写进命令行），再恢复：

   ```bat
   set "AUTOBID_RESTORE_URL=postgres://USER:PASSWORD@127.0.0.1:5432/autobid_restore?sslmode=disable"
   ops.bat restore --dir D:\backup\autobid-2026-11-06 --target-database-url-env AUTOBID_RESTORE_URL --data-root D:\autobid-restored
   ```

3. 恢复会先校验备份，再逐个校验文件哈希和数据库版本，任何一步不符都会失败。
4. 把 `.env.local.bat` 的 `AUTOBID_DATABASE_URL` 指向新库，把 `AUTOBID_FILEWORK_DIR`、`AUTOBID_EXPORT_DIR`、`AUTOBID_EVIDENCE_DIR` 指向 `--data-root` 下的 `filework`、`exports`、`evidence`。
5. 放回模型主密钥，再启动服务。

## 5. 升级

1. `ops.bat check`：确认没有在途作业。有就等完成或在页面取消。
2. 停止服务。
3. 备份并校验（第 3 节）。**没有通过校验的备份不要升级。**
4. 更新代码，运行 `start.bat`。数据库在启动时自动迁移。
5. 看启动窗口和页面“运行能力”，确认文档引擎、Mermaid、OCR 自检通过，再让业务人员开始提交。

升级后的行为：

- 历史数据和产物文件不变。演练比对了 17 张表的全部旧列和所有产物哈希。
- 升级前的导出如实显示为“仅预览稿”，不会变成最终稿。
- 升级前的项目不启用写作门禁，也不显示故事板入口，新项目默认启用。
- 升级时中断的索引构建显示为失败（`INTERRUPTED`），重新构建即可，已算好的向量会复用。
- 作业固定提交时的执行版本。升级 WPS 或 OCR 后，排队中按旧版本提交的最终稿或解析作业会以 `RUNTIME_UNAVAILABLE` 失败，用新请求重新提交。

升级到含 D4（成稿与提交，数据库代际 2）的版本后另有三点，都是有意为之：

- **一致性核验要重新运行一次。** 旧结论没有把正文与承诺台账比对过，升级后不再算当前结论，导出门禁显示“最近一次全文一致性核验已过期：核验规则已升级”。在“一致性核验”页点一次“重检矩阵并核验”即可。
- **升级前生成的最终稿不能直接走提交检查清单。** 它们没有回读自检记录，清单的系统项会显示不通过。文件本身没有变化、仍可下载；要作为提交文件，请重新导出一份最终稿。
- **新的最终稿必须填写投标人名称。** 封面和文件的作者属性都用它；不填时提交被拒绝，预览稿不受影响。

## 6. 回退

**回退只有一条路：恢复升级前的备份。不要让旧程序直接连接已升级的数据库。**

原因是实测结果：旧程序连上已升级的库时能正常启动、不报任何错，却会重放旧版建表脚本，静默改写约束函数和触发器。在 `8b48a4b` 上实测，改写了 3 个函数和 1 个触发器，其中包括保护导出快照不被修改的 `export_jobs_immutable`。

从本版本起，数据库记录单调的代际号（`schema_version.generation`），程序发现数据库比自己新时拒绝启动。这只保护本版本之后的回退；更早的程序没有这段检查，所以上面这条规则一直有效。

回退步骤：

1. 停止服务。
2. 按第 4 节把升级前的备份恢复到新库和新目录。
3. 切回旧版本代码，把配置指向恢复出的新库和目录，启动。
4. 升级之后产生的数据不在这份备份里。回退前先导出需要保留的成稿。

## 7. 常见故障

| 现象 | 处理 |
| --- | --- |
| 文档引擎“自检失败” | 确认在已登录的桌面会话里运行，手动打开 WPS 看有无弹窗（激活、更新提示会卡住 COM）。关掉弹窗后重启服务 |
| 导出长时间不动 | 单次刷新超时默认 180 秒。超时后结束本次启动的进程，不影响用户自己打开的 WPS。页面可以取消 |
| OCR“检查中”很久 | 服务启动时要加载模型，最多等 2 分钟。看 `autobid-ocr` 窗口是否报错 |
| 语义检索显示“仅全文” | 模型未配置、不可达或授权到期。检索如实退回全文和关键词，功能可用。到期后的选择见 LOCAL_RUNTIME.md 3.4 |
| 启动时报“数据库已被更新版本升级” | 程序比数据库旧。换回新版程序，或按第 6 节恢复备份 |
| 磁盘空间不足 | 先备份再清理。不要手动删除 `filework`、`exports`、`evidence` 下的文件：数据库引用它们，缺文件时下载和核验会失败 |
| 端口被占用 | 改 `AUTOBID_HTTP_ADDR`，或结束占用端口的程序 |
| 页面提示输入令牌 | 服务设置了 `AUTOBID_API_TOKEN`，在页面的令牌设置里填写 |

## 8. 关闭某项能力

能力关闭后拒绝新提交，并告诉用户原因，不会假装成功或降级成别的结果。S7 用真实重启逐项验证过。

| 配置 | 效果 |
| --- | --- |
| `AUTOBID_OFFICE_ENGINE=off` | 不启动 WPS / Word。最终稿和 PDF 被拒绝，只能导出 DOCX 预览稿，已有产物仍可下载 |
| `AUTOBID_FILE_PROCESSING_ENABLED` 不设 | 关闭原件留存和材料处理，粘贴导入仍可用。关闭前已提交的解析作业不再执行，到提交时固定的截止时间（默认 15 分钟）自动结束，等待它的 Agent 意图会收到结果；截止前重新启用则继续处理。文档页仍显示必需材料清单（仍参与导出门禁，可改为非必需）和作业列表（可取消） |
| `AUTOBID_AGENT_EXPORT_ENABLED` 不设（默认） | Agent 不能提交导出，页面导出不受影响 |
| 不配置 `AUTOBID_OCR_URL` | 扫描件被拒绝，不会当空白文件导入 |
| 不配置 `AUTOBID_EMBEDDING_URL` | 使用全文和关键词检索 |

## 9. 首版范围与已知限制

- **解析范围只含招标文件。** 知识库增强解析（S5b）和企业证明材料 OCR 候选（S5c）没有实现。知识库上传的扫描件不经候选核对，识别结果直接入库；证明材料只留存原件，不做识别。
- **操作人只是审计声明，不是登录身份。** 页面上的“当前操作人”由使用者自己填写，粉队和红队的作者分离按它判定，可以被伪造。可信身份和角色权限要等 R2 / Phase 7，所以 Agent 导出入口保持关闭。
- **没有做过真实断网演练。** 验收检查了页面不访问本机以外的地址、模型不可达时能退回，但没有实际拔网线。
- **没有做过长时间运行和负载测试。** 文档引擎同一时间只处理一个文档。
- **提交检查清单只是核对记录。** 清单“已全部处理”表示系统可查项通过、人工项有人确认过，不表示已在交易平台提交；签章、平台导入和上传都在系统之外完成，系统只记录谁在什么时候确认的。没有在任何交易平台的投标文件制作工具里验证过成稿能否导入。
- **证明材料原件不合入成稿。** 成稿里的《证明材料索引》列出原件及其页码范围，原件扫描件要由投标人按索引顺序另行附入。
- **所有验收都是工程验收。** 模型是脚本替身，业务质量、真实投标效果和生产可用性都没有验证。
