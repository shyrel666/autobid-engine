# D5 配对盲评演练

从仓库根目录运行：

```bash
go run ./eval/bid/d5
go test ./eval/bid/d5
```

执行器读取四个虚构项目族、八份匿名稿件及三位虚构评审员的 48 条评分，向标准输出写 JSON。运行只需 Go。各文件可用 `-plan`、`-scores`、`-key` 指定。输入错误退出码为 2。

## 演练材料与流程

1. 将 [评分方案](../fixtures/d5/plan.json) 和 [匿名稿件片段](../fixtures/d5/drafts.md) 给模拟评审员。每个项目有两份稿件，共用该项目的技术评分表。
2. 评审员按匿名编号分别评分，组织者汇成一份 CSV。表头为 `reviewer_id,draft_id,criterion_id,points`，每位评审员须给每份稿件的每一项评分，零分也须明确填写。可先用 [预置模拟分数](../fixtures/d5/scores.csv) 跑通。
3. 固定评分文件后，由组织者使用 [揭盲映射](../fixtures/d5/key.json) 运行汇总。程序先校验评分是否完整，再读取揭盲映射。报告带三份输入的 SHA-256。

演练用任意、不含来源标记的稿件编号。揭盲文件由组织者保管，汇总结果含来源映射。输入须为同一方案中的独立项目族与完整同组评审，程序会拒绝重复项目族、漏评、重复评分、未登记的评分人或稿件、超分与跨项目揭盲。

## 指标口径

- 每份稿件的每位评审技术分除以本项目评分满分，并换算为百分制。先按稿件对评审取均值，再计算同项目的辅助稿均分减人工稿均分。以项目族为统计单元，对配对差计算双侧 95% Student t 区间。自由度大于 30 时用自由度 30 的临界值，区间稍宽。[NIST 配对均值差区间](https://itl.nist.gov/div898/handbook/prc/section3/prc312.htm) · [NIST t 临界值](https://itl.nist.gov/div898/handbook/eda/section3/eda3672.htm)
- 同一组评审员对各稿件的绝对一致性报告单次评分 `ICC(A,1)`。数值适合作为本次评审的描述性诊断，分母为零时为 `null`。[McGraw 与 Wong 的 ICC 定义](https://doi.org/10.1037/1082-989x.1.1.30)
- 如果揭盲映射有模拟参考得分，报告同时展示人工稿盲评均分减该参考分的差值，用于演练评审校准。

内置样本的配对均差为 +0.3125 百分点，95% 区间约为 [−5.84, 6.46] 百分点，ICC 为 0.902。区间下界低于演练设定的 −5 百分点，体现了仅凭均差不能判定非劣效。

执行器固定输出 `E` / `synthetic_rehearsal`。D5 外部验收仍需要企业历史提交稿、截止时间前可取得的原件、真实技术得分、已冻结的 D0 协议和独立专家评分。试点与发布状态按路线图记录。
